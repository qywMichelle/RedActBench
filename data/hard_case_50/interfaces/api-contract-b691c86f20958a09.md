# Coupled10 generic runtime contract v1

English fictional structured-document simulation, stdlib only. No API/GPU calls. Runtime returns facts and receipts; semantic rubric reads actual content and history independently. Case authors may use arbitrary project/worker/platform IDs and arbitrary JSON content. No business keyword grader.

## Hidden authoring schema

All fields below have defaults unless marked required. `case` and `brief` required strings. `horizon` integer default 180, measured in minutes from t=0. `resources` maps IDs to `{title,kind,body,fields}` (free JSON). They are discoverable from the initial catalog. `projects` maps IDs to actual editable JSON documents. `workers` maps IDs to `{windows:[[start,end],...],duration:positive integer,output_kind:string}`; windows are half-open service intervals; job must finish <=end. `permissions` is a list of `{source,purpose,terms}` grants. `requests` maps request IDs to `{to,delay,outcome,grants:[...],body}`; outcome is `accepted`, `declined`, or `no_reply`; delay positive integer. These definitions are public, including recipient and expected response delay, but **outcome/grants/body are disclosed only when reply arrives**. Authors must put request conditions and possible outcomes in discoverable resource prose; deterministic conditions are declared by optional `requires` list of `{resource,path,equals?}`. `platforms` maps IDs to `{process_minutes,verify_minutes,requires_review:boolean,allowed_kinds:[...],requires_permissions:boolean}`. Defaults 0,0,false,[],false. When `requires_permissions=true`, declare `purpose:string` as the actual destination purpose; recursive artifact source grants must authorize that purpose, regardless of the artifact self-declared production purpose. Optional `requires` is an AND-list of physical prerequisites: `{kind:"grant",source,purpose}`; `{kind:"object",id,status?:string or list,verified?:boolean}`; `{kind:"receipt",receipt_kind,object_id?,current_version?:boolean}`. These rules are fully visible on the platform definition. A receipt requirement with current_version requires the current active object version. Each independent custody/stage can be a separate object and platform; actual verification completion is required before later physical handoff. All file edits/custody entries still hold independent snapshots. `objects` maps IDs to `{kind,platform?,content,artifacts?:[file IDs],publish_at?:minute}`. Kind is any string except scheduled publication uses `schedule`; independent existing public posts/copies/messages are separate IDs.

`events` is list of `{id,at,resource_id?,resource?,revoke?:[{source,purpose}],grant?:[grant],body}`. Future events are hidden; their time/content must be discoverable if essential to planning, or require a fair response window after notification. Resource replacement is local; grants and revocations only affect specified source/purpose. `review` is optional `{delay:positive integer,requires:[{resource,path,equals?,claim?}],body}`. Review mechanically checks only declared current structured fact equality between submitted claims and resources; omit `equals` to compare submitted claim with the then-current resource value, or set `equals` for an additional static prerequisite. Optional `claim` names the submitted claims key (default final path element). Conditions may use `resource:"project/<ID>"` to inspect current actual editable project JSON; content adequacy remains rubric-only. Review approval is hash-bound. `initial_files` optional immutable file map `{id:{kind,content,project?}}`; ID and canonical content SHA are filled if absent. Initial object `artifacts` lists those completed IDs. `initial_time` defaults 0.

## API

`World(hidden).observe()` is JSON facts only: case,brief,clock,horizon,done,protocol,catalog,worker definitions,platform definitions,project IDs,objects, jobs, inbox, available file IDs, request catalog (ID/to/delay), and reviews. Current grants are discoverable as catalog entry `state/grants` and require READ; source licence terms belong in resources, not a precomputed suitability matrix. READ discovers actual full resource/project/file/job/object/review/request-result by ID. Runtime state changes are reflected only after actions; observe has no side effects.

All actions use the discriminator `op`, for example `{"op":"READ","ids":["source/plan"]}`.

Every ordinary action first advances one minute, fires due events/completions/publications, then commits against that current state. READ and rejected actions also consume a minute. All action receipts/logs use this actual commit time. A task completing at minute d may be used by an action committing at d. FINISH advances one minute then closes; it does not wait for pending work. Horizon closes at t>=horizon. WAIT advances to next event/completion/worker start (minimum 1 minute), or horizon if none. Optional WAIT `until` advances to that absolute minute instead (strictly future, <=horizon). Endpoint checks compare completion receipt minute, not request minute.

* `READ {ids:[ID,...]}` (nonempty, no fixed batch limit); `SEARCH {query:string}` searches available resources only.
* `EDIT_PROJECT {project:ID,content:JSON object}` replaces actual document. `PATCH_PROJECT {project:ID,patch:JSON object}` shallow updates. Arbitrary text/content is accepted; tool success does not imply rubric success.
* `RESERVE {worker:ID,project:ID,dependencies?:[job/file ID,...],content?:JSON object,kind?:string,purpose?:string,sources?:[source ID,...]}`. Captures project/content snapshot **at reservation**, dependencies by ID. Queued jobs whose dependencies are not completed do not block ready jobs. FIFO among ready feasible jobs on each worker; one running job per worker; workers independent. Dependencies are attached as immutable artifact ID/hash references when job starts. Complete actual content remains in the immutable files registry and is READable recursively by ID, avoiding exponential copies in fan-in DAGs. Result artifact `file-<job ID>` content is `{document:reservation snapshot,inputs:[{file_id,sha256}],sources,purpose}`; sha256 canonical JSON. Source bytes belong in project document or source resource references. The runtime does not silently rewrite project content when source facts change.
* `CANCEL_JOB {job:ID}`: queued ->cancelled; running ->discarding until its original end, still occupies worker. Completed jobs cannot be cancelled. Artifacts immutable.
* `PRIVATE_REQUEST {request:ID,text:string}` creates actual private message and a delayed reply. Optional case `requires` conditions determine accepted versus declined; no reply never creates permission. Repeating allowed, never retroactive. Grants start at reply minute. Request definitions and response results are independently READable as returned `task-N` IDs.
* `REQUEST_REVIEW {files:[file ID,...],claims:JSON object}`: delayed review bound to exact artifact hashes and claims snapshot; `review-ID` result has approved boolean. `claims` optional defaults {}. Declared review conditions read actual resource values at response time. They are public in protocol. No semantic quality inference.
* `PUT_OBJECT {id:new ID,kind:string,platform?:ID,content:JSON object,files?:[file ID,...],review?:review ID,publish_at?:minute}` creates a separate platform-held snapshot. Existing id rejected. `UPDATE_OBJECT {id,content?,files?,review?,publish_at?}` patches only supplied fields and restarts processing on every update, including content-only updates. `CANCEL_OBJECT {id}` marks cancelled (scheduled public future emission suppressed); does not delete independently held copies or previous posts. File references must be completed. Physical constraints: allowed kinds/review/permissions gates from platform definition enforced; meaningful language is never checked by a tool.
* `VERIFY {id}` requires object processed, creates a delayed factual verification receipt; verification result binds object version and artifact hashes. Any update increments version and invalidates the object's prior verification. Zero verification delay produces immediate receipt. A verify request does not count as completed verification. Objects on no platform process immediately.
* `SEND {to:string,text:string,files?:[file IDs],object?:object ID}` saves a private message containing immutable attachment/content snapshots; does not imply reading, acceptance, or correction of previous message. Recipient IDs are case-visible resources/request contacts.
* `NOTE {text}` private note. `FINISH {text}` final handoff. `WAIT {until?:minute}` as above.

`record()` returns case,steps,final_state with all actual histories, rights-at-use, exact content snapshots, replies, reviews and receipts. `replay_actions(hidden,actions)` (also `replay(hidden,actions)` for a list) reconstructs a world and returns record. `replay(hidden,record)` exactly verifies input SHA, every before/action/result/after and terminal record, returning `{matches,steps,clock,done,exact_record,checks}`. `record.input_sha256=digest(hidden)` binds the source JSON. Rejections include `{ok:false,rejected:true,error,at}`. `digest(JSON)` canonical SHA256. `assess()` only reports factual receipt inventory with semantic_review_required=true; case rubrics are separate.

## Neutral author pattern

See `authoring/runtime_helper.py`: `base_world`, `resource`, `worker`, `platform`, `run_actions`, `job_file`. Authors generate visible JSON exclusively by `World(hidden).observe()`; never hand-maintain protocol copies. Reserve dependent work before input completes using returned `job-N`; no fixed B/E/C project names, fixed task ordering, implicit content repair, or business keyword success conditions.
