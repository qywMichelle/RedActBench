# hard_case_02

Ten independent English **hard development episodes** with coupled commissions, scoped authority, cross-source verification, shared resources and discoverable business deadlines. This package is separate from the original400 and the preceding20 in `data/hard_case`.

There are82 goals and164 rubric checks, with74 full authored reference/alternative/negative/boundary records. Canonical reference length averages50.2 tool calls; the easiest authored observed legal routes average46.9 calls. These are measured routes, not a global minimum proof or empirical model difficulty calibration.

The cases cover survey science, outage coordination, bilingual publishing, shared workshop tools, radio archives, sports fixtures, device repair, pantry inventory, library withdrawal and theatre tickets. See [Chinese case index](case-summary-zh.md), [manifest](manifest.json) and [design comparison](design-outline.md).

## Inputs and runtime

Inputs are **text only**, with multiple textual source cards/messages/contracts/logs and structured JSON artifacts. They are not visual/OCR/audio comprehension tasks, actual rendered media, or real financial/physical operations. See `input-format.json`.

Supply the public `tool-interface.json` and only the current `World(hidden).observe()` observation to a candidate. Never expose hidden worlds, rubrics, future events, reference records, seed provenance or reviews. `runtime/runtime.py` is package-local. Independent objects, immutable job inputs, scoped private sends and actual current-version receipts matter; local drafts and owner FINISH do not automatically perform separate deliveries.

Closing-minute completion is inclusive where the public clock/calendar says so; +1 is late. The strict pre-QA event order in n01 and authority-before-use/service prerequisites remain strict. Limits derive from visible business windows and processing/verification costs, not hidden evaluator waits.

## Verification and evidence

```bash
python data/hard_case_02/verify.py
python data/hard_case_02/audit_retained.py
python data/hard_case_02/build.py --out /tmp/hard_case_02-rebuild
```

The builder requires a new output directory and reconstructs all104 core JSON files for byte comparison. `verification.json`, `retained-verification.json`, `rebuild-comparison.json` and `protocol-tests.json` record actual CPU checks. CPU replay is not a semantic success score.

`reviews/independent/` retains R1–R3 and an explicit extra R4 timing-clarification review. R1 had8 accept/2 revise; subsequent accepted versions repair the n07 reference disclosure and n10 stale hold-status directions. Original reports and wrong positive author annotations remain retained with errata. R1 used a fresh separate staged reviewer; later rounds were iterative. `reviews/primary/` contains the informed final acceptance. No candidate-model experiment was added.

`historical/` retains exact old worlds/records and input manifests; `source-path-map.json` resolves original paths without substituting newer inputs. `seed-provenance.json` binds ten distinct unused original hard seeds and stored successful input/runtime/trace judgments to hashes. Source permissions and identities never carry into these fictional new stories.

## Limits

All cases share the job/receipt engine and owner handoff, and independent-copy maintenance remains common. n08 recipient feedback supplies the specific negotiated allocation/credit; those supplied calculations are excluded from model-reasoning claims. Human spot-checks are suggested, not performed. No empirical candidate-model difficulty, judge calibration or formal split claim is made: `formal_evaluation_ready=false`. No review HTML is generated.
